# 今、何から逃げたい？

[![License: CC BY 4.0](https://img.shields.io/badge/License-CC%20BY%204.0-lightgrey.svg)](https://creativecommons.org/licenses/by/4.0/)

都市の中で一時的に落ち着ける場所とルートを探す、スマートフォン向けWebアプリです。

## 何をするのか

利用者が「人混み」「騒音」「疲れ」「一人になりたい」など、今の状態を選びます。
青山・表参道・渋谷周辺の空間データから、5〜15分で歩ける「回復ルート」を推薦します。

目的地から探す一般的な地図ではなく、**今の気分から都市の過ごし方を探す**ことが特徴です。

## ゴール

- OpenStreetMapから候補地点を約100地点抽出する
- 空間条件で候補を30〜40地点に絞り込む
- 最終的に24地点以上の「都市の余白」データを作成する
- 12〜15地点だけ現地確認する
- 6種類の状態に対応する回復ルートを12本程度作成する
- スマートフォンで使えるWebアプリを完成させる
- GitHub Pagesで公開する
- 10〜20人に利用してもらい、使いやすさと実用性を検証する
- アプリ、データを成果物として提出する

## 成果物

1. スマートフォン向けWebアプリ
2. 都市の余白データセット（地点・評価・写真・観察メモ）
3. 状態別の回復ルート
4. 利用者アンケートと検証結果
5. 卒業論文・発表資料

## 使用ツール

- ChatGPT / Codex：設計、データ整理、分類、実装、分析
- OpenStreetMap / Overpass Turbo：候補地点の検索・抽出
- QGIS：距離や周辺環境などの空間分析
- 国土地理院地図：地図・周辺環境の確認
- Googleスプレッドシート：地点データと評価の管理
- Googleフォーム：現地調査・利用者アンケート
- HTML / CSS / JavaScript：Webアプリの制作
- Leaflet / GeoJSON：地図とルートの表示
- geojson.io：ルートデータの作成・確認
- GitHub Pages：Web公開

## 完成までのステップ

### 1. 完成するアプリの範囲を決める

対象地域を青山学院大学周辺、表参道、渋谷・宮益坂周辺に限定します。

利用者が選べる状態を、次の6種類に決めます。

- 人混みから逃げたい
- 騒音から逃げたい
- 疲れている
- 一人になりたい
- 暑さを避けたい
- 気分を変えたい

利用者が状態と「5分・10分・15分」の歩行時間を選ぶと、おすすめ地点と回復ルートが表示されるアプリを完成目標にします。

### 2. OSMから候補地点を抽出する

Overpass Turboで対象地域を指定し、OpenStreetMapのタグを検索します。

| OSMタグ | 候補にする場所 |
|---|---|
| `leisure=park` | 公園 |
| `leisure=garden` | 庭園 |
| `amenity=bench` | ベンチ |
| `amenity=shelter` | 屋根・避難場所 |
| `amenity=library` | 図書館 |
| `amenity=cafe` | カフェ |
| `shop=convenience` | コンビニ |
| `highway=pedestrian` | 歩行者道路 |
| `highway=footway` | 歩道 |
| `highway=living_street` | 生活道路 |

検索結果をGeoJSONで保存し、Googleスプレッドシートに地点名、位置、OSMタグ、営業時間、アクセス条件、出典URLを記録します。

候補地点は約100地点を目標にします。

### 3. 空間条件で候補を絞り込む

QGISで候補地点を表示し、次の条件を比較します。

- 駅からの距離
- 幹線道路からの距離
- 公園・緑地からの距離
- 歩行者道路や歩道への接続
- 他の候補地点との距離
- 屋内・屋根の有無
- 5〜15分で歩けるか

この結果をもとに、候補を30〜40地点に絞ります。ここでは「静かである」と断定せず、空間条件から利用に向いている可能性を比較します。

### 4. 最終候補だけ現地確認する

30〜40地点の中から、アプリに掲載する可能性が高い12〜15地点を現地確認します。

スマートフォンで写真を撮影し、Googleフォームに次の項目を入力します。

- 実際の静けさ
- 人通りの多さ
- 人目の気になりやすさ
- 座れる場所の有無
- 日陰・屋根の有無
- 緑の多さ
- 滞在しやすさ
- 入口の分かりやすさ
- 工事・閉鎖・立入制限の有無
- 現地での観察メモ

各項目は1〜5点で評価し、写真と現地メモを地点データに追加します。

### 5. 一定のルールでデータを整理する

地点データを、次の3種類に分けて管理します。

1. **元データ**：OSMタグ、施設名、位置、営業時間など
2. **空間分析データ**：駅・幹線道路・緑地からの距離、徒歩時間など
3. **現地確認データ**：静けさ、人目、座りやすさ、写真、観察メモなど

現地確認データは、すべて5段階で統一します。

```text
1：非常に低い
2：低い
3：普通
4：高い
5：非常に高い
```

ChatGPTやCodexは、観察メモの分類、地点紹介文の作成、データ項目の確認に使います。最終的な評価点は、決めた基準と現地確認の結果に基づいて確定します。

### 6. 状態別の推薦ルールを作る

利用者の状態ごとに、重視する評価項目を決めます。

| 利用者の状態 | 重視する項目 |
|---|---|
| 人混みから逃げたい | 人通り、駅からの距離、空間の広さ |
| 騒音から逃げたい | 静けさ、幹線道路からの距離、緑 |
| 疲れている | 座りやすさ、日陰、駅からの距離 |
| 一人になりたい | 人目の少なさ、滞在しやすさ |
| 暑さを避けたい | 屋内、屋根、日陰 |
| 気分を変えたい | 緑、景観の変化、普段と違う道 |

例えば「疲れている」の推薦点は、次のように計算します。

```text
疲れ回復スコア
= 座りやすさ × 3
+ 日陰・屋根 × 2
+ 駅からの近さ × 2
+ 静けさ × 1
```

このルールで24地点を順位付けし、状態ごとに2本程度、合計12本のルートを作成します。

### 7. 回復ルートを作成する

QGISやgeojson.ioで、歩道・歩行者道路を通る5分、10分、15分のルートを作成します。

各ルートに、次の情報を付けます。

- ルート名
- 対応する状態
- 所要時間
- 距離
- ルートの特徴
- 立ち寄り地点
- 推薦理由

最初から自動ルート検索を作らず、GeoJSONでルートを用意します。

### 8. Webアプリに実装する

HTML、CSS、JavaScript、Leafletを使い、次の画面を作ります。

- 状態を選ぶ画面
- 歩行時間を選ぶ画面
- おすすめ地点とルートを表示する画面
- 写真、評価、推薦理由を確認する画面
- 利用後の評価を入力する画面

地図上では、静かな場所を青・緑、騒がしい場所を赤、おすすめルートを光る線で表示します。

### 9. 公開して利用者に使ってもらう

GitHub Pagesで公開し、スマートフォンで利用できることを確認します。

10〜20人に、状態と歩行時間を選択して実際にルートを使ってもらいます。利用後にGoogleフォームで、次の項目を評価してもらいます。

- 操作の分かりやすさ
- 地図の見やすさ
- 推薦結果への納得感
- 実際に歩きたいと思ったか
- 歩いた後の気分の変化
- また使いたいか

### 10. 改善して最終成果物にまとめる

アンケート結果をもとに、評価項目、推薦ルール、ルート、画面を改善します。その後、制作過程と利用者評価を卒業論文にまとめます。

## 完成の判断

次の流れがスマートフォンで問題なく動作すれば、アプリの完成とします。

```text
状態を選ぶ
  → 歩行時間を選ぶ
  → おすすめルートを見る
  → 実際に歩く
  → 利用後に評価する
```

## 研究の問い

感情や状態を起点に都市空間を推薦することで、一般的な地図検索よりも、自分に合った一時的な回復空間を見つけやすくなるのか。
